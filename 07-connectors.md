# 07 — Connectors

*Where the AI may read real work from, what it may write to, and which tools are admitted to the workflow.*

> **How to fill this in.** This is a permissions file as much as a tools list. For every source: may the AI read it, write to it, or neither? For every tool: is it in, fenced, deferred, or out — and what would change that? Principles first, so that future decisions about tools you haven’t heard of yet can be made without reopening the argument.

## The governing principles

*Worked examples from a real stack; keep what’s true for you.*

1. **One permanent home.** [Name it.] Everything else — cloud documents, notebooks, chat threads — is a working surface. Synthesis returns to the permanent home or it doesn’t count.
2. **Plain text where possible.** Every serious tool has a priesthood; prefer tools whose source stays legible without the tool. Binary formats and WYSIWYG instruments interpose a wall between the writer and the content.
3. **A tool earns entry only if it reduces an inbox.** Deferred tools stay deferred until they prove this.
